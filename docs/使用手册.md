## 1. 先搞清楚三个角色

刚上手最容易搞混的就是"我该在哪台电脑上装什么"。记住这张表:

| 角色 | 装在哪台电脑 | 程序 | 干什么 |
|---|---|---|---|
| **被控端** | **要被远程操作的那台**(比如家里的电脑) | `RemoteDesktop-Host.exe` | 把屏幕传出去,接收并执行对方的鼠标键盘操作 |
| **主控端** | **你正在用的那台**(比如公司的电脑) | `RemoteDesktop-Client.exe` | 显示对方屏幕,把你的鼠标键盘发过去 |
| **中转服务器** | 一台有公网 IP 的服务器(**可选**) | `python -m relay.main` | 双方都连不通时,在中间转发数据 |

> 一句话:**想操作谁,就在谁那台电脑上开"被控端"**。

中转服务器不是必须的——同一个局域网(比如家里、公司内网)直接用"直连"就行。

## 2. 快速上手

### 2.1 Windows 用户(不需要装 Python)

**第一步:拿到程序。** 三种途径任选:

| 途径 | 适合谁 | 怎么做 |
|---|---|---|
| **A. 下载 CI 构建产物** | 想马上用 | 打开仓库 **Actions** 页 → 点最新一次 `build-windows` → 页面底部 **Artifacts** 下载 `remotedesktop-windows` → 解压 |
| **B. 下载正式发布版** | 想要安装向导 | 打开仓库 **Releases** 页 → 下载 `RemoteDesktopSetup.exe`(安装版)或 `RemoteDesktop-Windows-Portable.zip`(免安装版) |
| **C. 自己编译** | 想改代码 | 装好 Python 3.10+,双击 `build\build_windows.bat`,几分钟后产物在 `dist\` |

> 途径 B 的 Release 需要仓库维护者打个 tag 才会生成(`git tag v1.0.0 && git push origin v1.0.0`)。

**第二步:在"被控端"电脑上。** 双击 `RemoteDesktop-Host.exe`,会弹出一个黑色控制台窗口:

```
========================================================
 远程桌面 - 被控端 已启动
 连接方式: 直连
 请确保对方可访问本机地址: <本机IP>:8765
 访问密码: tY8m5H987u
 接收文件保存到: C:\Users\你的用户名\RemoteDesktop-收到的文件
 请将以上连接信息告知需要连接的一方,在网页客户端中填写
 按 Ctrl+C 退出
========================================================
```

⚠️ **这个窗口不能关**,关了远程连接就断了。可以最小化(任务栏托盘里有图标)。

把 **本机 IP** 和 **访问密码** 告诉对方。查本机 IP:按 `Win+R` → 输入 `cmd` → 回车 → 输入 `ipconfig` → 找 "IPv4 地址"(通常形如 `192.168.1.5`)。

**第三步:在"主控端"电脑上。** 双击 `RemoteDesktop-Client.exe`,浏览器会自动打开控制页面:

1. 选 **直连** 标签
2. **被控端地址** 填 `192.168.1.5:8765`(对方 IP + 冒号 + 端口)
3. **访问密码** 填对方控制台上显示的密码
4. 点 **连接**

看到对方屏幕就成功了。

### 2.2 从源码运行(macOS / Linux / 想改代码的 Windows 用户)

```bash
git clone <仓库地址>
cd RemoteDesktop

python3 -m venv venv
source venv/bin/activate        # Windows 用 venv\Scripts\activate
pip install -r requirements.txt
```

被控端:

```bash
python -m host.main
```

主控端:

```bash
python -m client.main
```

> **Linux 被控端额外要求**:需要图形界面环境(X11)。纯命令行的服务器无法采集屏幕。
> 剪贴板同步需要 `xclip`:`sudo apt install xclip`。
>
> **macOS 被控端额外要求**:首次运行时系统会弹窗要求授予「屏幕录制」和「辅助功能」
> 权限(系统设置 → 隐私与安全性),否则看不到画面或无法控制鼠标键盘。

## 3. 两种连接方式怎么选

```
          能互相 ping 通吗?
                 │
        ┌────────┴────────┐
       是                 否
        │                  │
     【直连】          【中转】
   同一局域网 /       双方都在 NAT、
   已做端口映射       宽带无公网 IP
```

### 3.1 直连

最简单、延迟最低、不依赖第三方服务器。适用:

- 同一个 WiFi / 公司内网
- 被控端有公网 IP,或已在路由器上做了端口映射(把外网 8765 端口转发到被控端)

被控端默认监听 `0.0.0.0:8765`,用 `--port` 可改端口。

### 3.2 中转(穿透 NAT)

双方都在家庭宽带/4G 网络后面,互相连不通时使用。需要一台有公网 IP 的服务器跑中转程序
(部署方法见 [deploy_relay.md](deploy_relay.md),一条 docker 命令即可)。

**被控端**启动时加上中转地址:

```bash
python -m host.main --relay ws://你的服务器地址:8770
```

控制台会多显示一个 **会话码(ID)**:

```
 连接方式: 中转服务器 (ws://relay.example.com:8770)
 会话码 (ID): HH9FVVBHMM
 访问密码: tY8m5H987u
```

**主控端**在网页里选 **中转** 标签,填:
- 中转服务器地址:`relay.example.com:8770`
- 会话码:`HH9FVVBHMM`
- 访问密码:`tY8m5H987u`

> 中转服务器只是"传话筒",它**看不到**你的屏幕内容、按键和剪贴板——所有数据在
> 两端之间加密,中转服务器拿到的是无法解密的密文。详见[第 11 章](#11-安全须知)。

## 4. 界面与功能详解

连接成功后,顶部工具栏从左到右:

```
● 已连接: 我的电脑   32 ms  [只读观看]   清晰度[智能(自动)▼] 显示器[▼]  均衡 · 18.0 fps · 420 kbps · 本机 8ms   [发送文件][发送剪贴板][全屏][断开连接]
```

| 元素 | 含义 |
|---|---|
| **● 状态点** | 绿=已连接,黄闪=连接中/重连中,红=出错 |
| **延迟 (ms)** | 网络往返延迟。<100ms 绿色(流畅),100-300ms 黄色(可用),>300ms 红色(明显卡顿) |
| **只读观看** | 只在多人观看时出现,表示你当前没有操作权,只能看 |
| **清晰度** | 见[第 5 章](#5-清晰度与弱网调优) |
| **显示器** | 对方有多块屏幕时才出现,可切换看哪一块(多人观看时会一起切换) |
| **状态文字** | 当前画质档位 · 实际帧率 · 实际码率 · 被控端本机采集+编码耗时 |

> **"本机 XXms" 这个数字很有用**:如果它很大(比如 80ms)而延迟数字不高,说明卡顿的
> 原因是**对方电脑性能不足**(截屏和压缩画面就花了很久),这时候降低清晰度有用;
> 反过来如果延迟很高而"本机"很低,那是**网络问题**,换网络或让程序自动降档更有效。
> 鼠标悬停在状态文字上,还能看到更详细的信息:当前编码格式、本帧变化区域块数、
> 关键帧/增量帧/静止跳过的计数,以及**带宽判断结果**。最后这一项很有用——
> 显示"带宽已打满"说明降低清晰度确实能改善延迟;显示"带宽充裕(延迟来自链路
> 本身)"则说明这是跨国/移动网络固有的延迟,降清晰度帮助不大。

### 4.1 远端鼠标光标

画面里会叠加显示**对方的鼠标指针**(包括形状变化:普通箭头、文本 I 型光标、
调整大小的双向箭头等)。屏幕截图本身是不含指针的,这是单独采集后叠加上去的。

你自己浏览器的光标也会照常显示。高延迟时两个光标之间会有一段间距,那个间距
直观反映了当前的往返延迟。

被控端加 `--no-cursor` 可关闭这项同步。

### 4.2 鼠标和键盘

点一下画面就能开始操作,鼠标移动、左右键、中键、滚轮都会转发到对方电脑。

键盘支持组合键(Ctrl+C、Alt+Tab 等)、方向键长按连续移动、F1-F12 等功能键。

> ⚠️ 少数组合键会被你**本机的浏览器或系统**优先拦截,传不到对方,例如
> `Ctrl+W`(关闭标签页)、`Ctrl+T`、`Alt+F4`、`Win` 键。建议点 **全屏** 按钮后
> 再操作,全屏模式下被拦截的按键会明显减少。

### 4.3 复制粘贴

三种方式,按场景选:

| 想做什么 | 怎么操作 |
|---|---|
| 把**我这边**复制的内容,粘贴到**对方**电脑 | 先在本机复制(Ctrl+C),再点工具栏 **发送剪贴板**;或者点一下画面后直接按 **Ctrl+V** |
| 把**对方**复制的内容,拿到**我这边** | 对方按 Ctrl+C 后会自动同步过来,直接在本机 Ctrl+V 即可 |
| 浏览器不让读剪贴板 | 会自动弹出一个小窗显示内容,点「复制」按钮即可 |

> 剪贴板同步目前只支持**纯文本**,不支持图片和文件(传文件请用[文件传输](#6-文件传输))。
> 对方那边的变化会在约 1 秒内同步过来(采用轮询检测,不是实时事件)。

### 4.4 断线自动重连

网络抖动、对方电脑休眠唤醒后,客户端会自动重连(1秒→2秒→4秒…最多 10 秒重试一次),
无需手动操作。

只是网络抖动(对方程序没退出)时,重连会走一条**快速通道**:利用上次连接时
拿到的一次性令牌直接恢复加密会话,省掉一次耗时的密码运算(手机上这一步可能
要 100-300 毫秒)。对方程序重启过的话令牌失效,会自动退回正常的密码验证,
用户无感知。

重连期间画面上会盖一层**半透明遮罩**并显示"正在自动重连…"。这层遮罩有实际作用:
画面停留在断线前的最后一帧,如果没有遮罩,你很容易对着一张过期的画面继续点击,
而这些操作全部会丢失。遮罩会拦住点击,避免误操作。

## 5. 清晰度与弱网调优

### 5.1 五个档位

| 档位 | 分辨率缩放 | 画质 | 最大帧率 | 适合 |
|---|---|---|---|---|
| 极速 | 35% | 很低 | 8 fps | 极差网络(2G/拥堵),保证还能操作 |
| 流畅 | 50% | 低 | 12 fps | 弱网,优先响应速度 |
| 均衡 | 75% | 中 | 18 fps | 一般网络(默认起点) |
| 清晰 | 100% | 较高 | 24 fps | 良好网络 |
| 高清 | 100% | 高 | 30 fps | 局域网/光纤 |

### 5.2 智能模式(默认,推荐)

选 **智能(自动)** 时,程序会持续测量"发出一帧到对方确认收到"的延迟,自动在上面五个
档位之间切换。策略是**快降慢升**:

- **网络一变差,立刻降档**(必要时一次降两档),优先保证鼠标键盘跟手;
- **网络变好后,要连续 5 次测量都良好才升一档**,而且刚发生过严重拥塞时会进入冷却期
  暂不升档。

这样做是为了避免网络抖动导致画质来回跳变(那种忽清晰忽模糊的闪烁比稳定的低画质更难受)。

### 5.3 手动固定档位

网络状况你自己更清楚时,可以直接选固定档位。比如明知道是按流量计费的 4G,直接选"流畅"
省流量。

### 5.4 自定义

选 **自定义** 会展开三个滑块,分别调节:分辨率缩放(20%-100%)、JPEG 质量(10-95)、
最大帧率(1-30)。适合特殊场景,比如"我只需要盯着一个监控画面,画质要高但 2 帧/秒就够"。

### 5.5 省流量的原理(为什么静止时几乎不耗流量)

程序不是每帧都把整个屏幕传一遍,而是**只传变化的区域**:

- 画面**完全没变**(比如你在看一份文档没动)→ **一个字节都不发**
- 只有一小块在变(打字时的输入框、跳动的时钟)→ 只传那一小块
- 大面积变化(切换窗口、滚动页面)→ 才传整屏

实测在 1280x800 下,小块变化时的流量只有整屏传输的 **8%** 左右。所以按流量计费的网络
下,只要不频繁滚动页面,消耗比想象中小很多。

## 6. 文件传输

### 6.1 发送文件到被控端

把文件从**主控端**发送到**被控端**。两种方式:

- **拖拽**:直接把文件拖到画面上,松手即发送(会显示"松开即可把文件发送到对方电脑")
- **按钮**:点工具栏 **发送文件**,选择文件(可多选)

底部会显示传输进度条。文件保存在被控端的 `C:\Users\<用户名>\RemoteDesktop-收到的文件`
(被控端启动时控制台会打印实际路径,也可用 `--download-dir` 指定)。

**注意事项:**

- 大文件传输时会自动让路给画面和操作,不会把远程桌面卡死,但传输速度会受影响
- 单文件上限 2GB,同时最多 4 个传输任务
- 如果被控端已有同名文件,会自动改名为 `报告 (1).docx`,不会覆盖
- 文件名中的特殊字符会被自动处理,不会因为文件名问题写到意外的位置
- 被控端启动时加 `--no-file-transfer` 可完全禁用此功能

### 6.2 从被控端下载文件

需要机主在启动被控端时**显式开启**共享目录:

```bash
python -m host.main --share-dir ~/要共享的文件夹
```

开启后主控端工具栏会出现「远端文件」按钮,点开可以看到该目录下的文件列表,
点「下载」即可保存到本机。

出于安全考虑,对方**只能**看到并下载这个目录下的直接子文件:不会递归进
子目录,不跟随符号链接,也无法通过构造文件名访问目录之外的任何路径。
不加 `--share-dir` 时该功能完全关闭,对方连按钮都看不到。

### 6.3 关于声音

**当前版本不转发音频**,只有画面。

这不是遗漏,而是需要单独排期的一块工作:系统声音的采集是强平台相关的
(Windows 要走 WASAPI 环回、Linux 要走 PulseAudio monitor、macOS 需要装
虚拟声卡驱动),而且要做实时编码(Opus)和与画面独立的抖动缓冲——音频对
延迟抖动比画面敏感得多,不能直接复用现有的画面流控。如果你的使用场景确实
需要声音,可以提出来单独评估。

## 7. 手机 / 平板使用

主控端是网页,所以手机浏览器也能用:在手机浏览器打开主控端电脑的地址,或直接在手机上
访问被控端(需要能连通)。

触屏手势:

| 手势 | 效果 |
|---|---|
| 轻点 | 左键单击 |
| 拖动 | 移动鼠标 |
| 长按(0.5 秒) | 右键单击 |
| 双指上下滑 | 滚轮滚动 |

手机屏幕小,建议配合 **全屏** 按钮使用,并把清晰度设成"流畅"或"均衡"。

## 8. 多人观看

默认只允许一个人连接。被控端启动时加 `--max-viewers 3` 可以允许最多 3 个人同时连接:

- **第一个连上的人**持有操作权,可以动鼠标键盘、传文件
- **后续连上的人**是只读观看者,工具栏会显示黄色的"只读观看"标记,他们的鼠标键盘操作
  不会被转发
- **操作者断开后**,操作权自动移交给剩下的人中最早连上的那个,对方会收到"你现在拥有
  操作权"的提示

适合远程教学、多人一起看演示的场景。

> 注意:所有人用的是**同一个密码**,所以他们的信任级别是一样的——只读观看只是避免
> 多人同时抢鼠标造成混乱,不是安全边界。别把密码给不该操作这台电脑的人。
>
> 中转模式下受限于中转服务器的一对一配对机制,只支持一个连接。

## 9. 命令行参数完整说明

### 被控端 `python -m host.main`

| 参数 | 默认值 | 说明 |
|---|---|---|
| `--port` | 8765 | 直连模式监听端口 |
| `--bind-host` | 0.0.0.0 | 直连模式绑定地址。填 `127.0.0.1` 则只允许本机连接 |
| `--password` | 自动生成 | 访问密码。**不建议手动指定**,自动生成的更安全 |
| `--relay` | 无 | 中转服务器地址,如 `ws://1.2.3.4:8770`。不填则用直连 |
| `--id` | 自动生成 | 中转模式的会话码 |
| `--monitor` | 1 | 采集哪块屏幕。1=主显示器,0=所有屏幕拼成的大画面 |
| `--host-name` | 计算机名 | 显示给对方看的名字 |
| `--download-dir` | 用户目录下 | 接收文件的保存位置 |
| `--no-file-transfer` | 关 | 禁用文件接收 |
| `--share-dir` | 无 | 共享给对方下载的目录。不填则对方无法下载任何文件 |
| `--no-cursor` | 关 | 不同步远端鼠标光标 |
| `--max-viewers` | 1 | 允许同时连接的人数 |
| `--no-tray` | 关 | 不显示系统托盘图标 |
| `--log-level` | INFO | 日志级别。排查问题时用 `DEBUG` |

### 主控端 `python -m client.main`

| 参数 | 默认值 | 说明 |
|---|---|---|

## 10. 常见问题排查

### 双击 exe 没反应 / 窗口一闪而过

最常见的原因是**端口被占用**——比如已经开着一个被控端/主控端了,又双击了一次。
两个程序现在都会在启动失败时留下明确提示,不会再"什么都没发生":

- **被控端**(有控制台窗口):失败时会打印原因,并停在"按回车键退出..."不会自动关闭,
  可以把提示内容截图发过来
- **主控端**(没有控制台窗口,双击直接开浏览器):失败时会弹一个错误提示框,并且
  在 exe 所在目录生成 `RemoteDesktop-Client-错误日志.txt`,把这个文件内容发过来即可定位

**先试试这几步:**
1. 任务管理器里看是不是已经有一个 `RemoteDesktop-Host.exe` / `RemoteDesktop-Client.exe`
   在跑了——有的话先结束掉,或者直接用已经在跑的那个,不用再开一次
2. 换个端口重试:被控端加 `--port 8766`,主控端加 `--port 8081`
3. 如果是杀毒软件/Windows Defender 拦截了(免安装的单文件 exe 有时会被误报),
   在拦截提示里选"仍要运行"或添加信任;这不是本项目的问题,PyInstaller 打包的
   单文件 exe 普遍会被误报,可以对照 GitHub 仓库里的源码自行确认

### 连不上

**先确认最容易错的三件事:**
1. 被控端的控制台窗口还开着吗?(关掉就断了)
2. IP 和端口填对了吗?格式是 `192.168.1.5:8765`,中间是英文冒号
3. 密码抄对了吗?区分大小写

**然后按提示信息对号入座:**

| 页面提示 | 原因与解决 |
|---|---|
| 一直卡在"正在连接..." | 网络不通。同一局域网内先用 `ping 对方IP` 测试;不通的话检查是不是连了不同的 WiFi |
| 连接被拒绝: 被控端当前连接数已满 | 已有人在连。等对方断开,或让被控端用 `--max-viewers` 提高上限 |
| 近期密码错误次数过多 | 密码连错 5 次会被临时封禁 2 分钟(防暴力破解),等一会再试 |
| 未找到该会话码对应的被控端 | 中转模式下会话码错了,或被控端还没连上中转服务器 |
| 该会话码已被占用 | 让被控端重启一次,会生成新的会话码 |
| 握手参数异常,已拒绝连接 | 可能有中间人篡改,或连到了版本不匹配的被控端 |
| 密钥协商失败 | 浏览器不支持 WebCrypto。请用 Chrome/Edge/Firefox 较新版本,且通过 `127.0.0.1` 或 https 访问 |

**Windows 防火墙**:第一次运行被控端时,Windows 会弹窗询问是否允许网络访问,一定要点
"允许访问"(专用网络必勾)。如果当时点错了,可以到「Windows 防火墙 → 允许应用通过防火墙」
里找到它重新勾选。

### 能连上但画面不动 / 全黑

1. 看状态栏延迟数字在不在跳。**不跳**说明连接其实断了,等自动重连
2. 延迟正常但画面不动 —— 对方屏幕可能真的没有变化(本程序静止时不传数据,这是正常的省流量行为),让对方动一下鼠标试试
3. 对方是 Linux:确认有图形界面,且 `DISPLAY` 环境变量正确
4. 对方是 macOS:检查是否授予了「屏幕录制」权限

### 鼠标点击位置不准

程序用的是相对坐标,理论上和缩放无关。如果确实偏了,让对方检查是不是在会话过程中改过
屏幕分辨率——改分辨率后重连一次即可。

### 能看到画面,但鼠标键盘没反应

- 工具栏是否显示黄色的**"只读观看"**?说明你没有操作权(见[第 8 章](#8-多人观看))
- 是否连接时提示过"对方系统暂不支持输入注入"?常见于 Linux 缺少图形环境、
  macOS 未授予「辅助功能」权限
- 先在画面上点一下(让画面获得焦点),再操作键盘

### 卡顿

看状态栏的 **"本机 XXms"** 判断瓶颈在哪:

- **本机耗时大(>50ms)** → 对方电脑性能不足。降低清晰度档位,或让对方关掉占用 CPU 的程序
- **延迟大(>300ms)但本机耗时小** → 网络问题。切到"智能(自动)"让它自动降档;
  如果用的中转模式,换一台离双方都更近的中转服务器
- **两者都不大但就是卡** → 可能是丢包。观察一下画质是不是在频繁跳变

### 传文件失败

| 提示 | 原因 |
|---|---|
| 被控端已禁用文件传输 | 对方启动时加了 `--no-file-transfer` |
| 文件过大 | 单文件上限 2GB |
| 磁盘空间不足 | 对方电脑磁盘满了 |
| 只读观看模式下无法发送 | 你没有操作权 |

### 托盘图标没出现

托盘是可选功能,不影响使用。Linux 某些桌面环境不提供托盘协议就不会显示,
程序会自动降级为纯控制台运行。

## 11. 安全须知

### 数据是怎么保护的

- **密码永远不上网**。它只在两端本地用于推导加密密钥(PBKDF2-HMAC-SHA256,20 万次迭代)
- **全程加密**。握手完成后,屏幕画面、鼠标键盘、剪贴板、文件全部用 AES-256-GCM 加密
- **中转服务器看不到内容**。它转发的是无法解密的密文,即使中转服务器被入侵,攻击者
  拿到的也只是"某个会话码在某时刻转发了多少字节",没有任何画面或按键内容
- **防重放**。攻击者即使截获了一条合法的加密指令(比如一次点击),也无法原样重发
- **防暴力破解**。同一来源密码连错 5 次会被临时封禁

### 使用建议

1. **不要用 `--password` 手动设简单密码**。自动生成的 10 位密码强度足够;手动设了弱密码
   程序会在控制台打出醒目警告
2. **用完就关掉被控端**。程序运行期间,任何知道 IP 和密码的人都能连进来
3. **密码通过可靠渠道告知对方**(当面说、电话说),别发在公开群里
4. **公网直连建议加一层 TLS**。直接把 8765 端口暴露在公网时,建议用 Nginx 之类做反向
   代理并配置 https/wss;中转模式可以直接给中转服务器配证书(见 deploy_relay.md)

### 已知的安全取舍

这是一个务实的工程实现,以下限制是设计时明确权衡过的,写在这里供你判断是否适用于
你的场景:

- **不具备前向安全性**:采用口令派生密钥而非 ECDH 临时密钥交换。如果密码在事后泄露,
  理论上可以解密之前被截获并保存的流量。这样做是为了让浏览器端只依赖标准的
  WebCrypto 算法,避免自行实现椭圆曲线密码学带来的正确性风险。需要更强保证的场景,
  请在传输层套 TLS。
- **中转模式下的限速会误伤**:被控端看到的来源 IP 是中转服务器的地址,无法区分真正的
  攻击者。因此中转模式下的封禁时间被特意缩短(15 秒而非 120 秒),以减少对正常用户的
  影响;真正的防线是足够强的密码。
- **多人观看不是安全边界**:所有人共用一个密码,只读观看只防误操作,不防恶意。

更详细的设计说明见 [architecture.md](architecture.md)。
